# GitHub Discussions Guide

Use GitHub Discussions for questions, controlled experiment proposals, computational reproductions, independent apparatus replications, failed replications, negative controls, signal-processing audits, and interpretation of the photodiode measurements.

## Recommended categories

- **Announcements**: Frozen captures, releases, protocol revisions, canonical-status changes, and maintainer notices.
- **General**: Broad discussion about the apparatus, experiment program, and repository organization.
- **Q&A**: Focused questions tied to an exact capture, file, script, parameter, figure, ledger entry, or result.
- **Ideas**: Preregistered experiment and analysis proposals with explicit controls and failure conditions.
- **Show and tell**: Reproductions, independent captures, null results, artifact diagnoses, alternate analyses, and apparatus improvements.
- **Polls**: Community priorities only. Polls are not experimental evidence.

## Evidence layers

Every substantive post should distinguish among:

1. **Acquisition fact**: what voltage waveform or instrument metadata was recorded.
2. **Signal-processing result**: what FFT, peak, ratio, decay, or log-cos procedure returned.
3. **Control result**: whether the same feature appears in dark, baseline, disconnected, dummy-load, mains-monitor, sham, repeat-device, or repeat-day conditions.
4. **Physical interpretation**: the proposed source of the signal and the remaining alternative explanations.

A reproducible FFT feature is a fact about the stored waveform. It does not by itself show that the feature was generated by optical confinement, a persistent photodiode state, or any specific WCT mechanism.

## Minimum standard for experimental reports

Include the repository commit, capture identifier, date and timing, photodiode and circuit, optical source and protocol, oscilloscope model and channel, coupling, grounding, shielding, trigger, sample rate, duration, vertical scale, bandwidth settings, raw waveform, calibration information, exact analysis command, dependency versions, analysis window, random seed, machine-readable outputs, uncertainty, and all available controls.

Because the canonical spectrum contains 60 Hz-spaced structure, mains and environmental pickup must be treated as a primary competing explanation rather than a minor caveat.

Use **PASS**, **FAIL**, or **INCOMPLETE** only when the decision gate was declared before analysis. Preserve failed replications and artifact findings. Move bounded software defects or implementation tasks to issues while keeping scientific interpretation and experiment design in Discussions.
